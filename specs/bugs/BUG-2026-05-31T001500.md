# BUG-2026-05-31T001500: Site deployment fails with "No source code found" when root directory is "./"

## Problem

Creating a Site with a GitHub repository and root directory set to `./` results in a failed deployment with the error "No source code found. Ensure your source isn't empty." from the open-runtimes executor.

**Actual behavior:** Deployment fails immediately; open-runtimes logs show "No source code found" twice (two coroutines).  
**Expected behavior:** The repository is checked out and the build proceeds normally.  
**Reproduction:** Create a Site connected to any GitHub repo, set root directory to `./`, trigger deployment.

## Root Cause Analysis

The builds worker normalizes the `providerRootDirectory` attribute before passing it to the VCS clone helper. The normalization only strips leading/trailing `/` characters via `trim($rootDirectory, '/')`. When the user sets root directory to `./`, this produces `'.'` (the `/` is stripped, the `.` remains).

The VCS clone helper uses git sparse checkout. When the sparse checkout pattern is `'.'` (a bare dot), git matches no files — because `.` is not a valid tracked filename in a git repository. The working tree after checkout is completely empty.

The builds worker then tars this empty directory and uploads it to storage. The open-runtimes executor receives a near-empty tar and reports "No source code found".

**Contributing factor:** The non-VCS template code path has an additional normalization step — a `while` loop that strips leading `./` prefixes — but the VCS code path is missing this normalization and also missing a guard for the bare `.` case.

**Risk level:** High — blocks deployment for anyone who enters `./` as root directory (a natural and common input).

## TDD Fix Plan

1. **RED**: Write a unit test for root directory normalization that asserts `./` → `''`, `./src` → `src`, `.` → `''`, `src/.` → `src/.` (pass-through for valid non-root paths).  
   **GREEN**: In the VCS branch of the builds worker, after `trim($rootDirectory, '/')`, add: (a) a `while` loop stripping leading `./` prefixes, (b) a guard that sets `$rootDirectory = ''` if the result is `'.'`.  
   **verify**: `docker compose exec appwrite test tests/unit/`

2. **RED**: Write an integration or mock test that builds a VCS-backed site with root directory `./` and asserts the deployment reaches `building` status (not `failed`).  
   **GREEN**: No additional code change needed after step 1.  
   **verify**: `docker compose exec appwrite test tests/e2e/Services/VCS`

**REFACTOR**: Extract the root directory normalization into a shared helper used by both the VCS branch and the template branch (they are currently duplicated with slightly different implementations).
