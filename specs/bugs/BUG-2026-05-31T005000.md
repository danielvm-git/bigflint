# BUG-2026-05-31T005000: error.phtml var_export circular reference warnings

## Problem

When an error occurs during site/function proxy execution, the error handler renders `error.phtml` with the exception's trace. In development mode, the template calls `var_export()` on each trace frame's `args` array to display the function arguments. Many of these arguments are complex objects with circular references (e.g., the Utopia DI container, Swoole server objects, closures). `var_export()` cannot handle circular references and emits:

```
Warning: var_export does not handle circular references in .../error.phtml on line 521
```

In the reported case, a site request timed out (HTTP 408), and the error handler rendered a trace containing ~18 injected framework objects — many with circular references — causing 24+ identical warnings per trace frame, flooding the logs.

**Expected behavior**: Error trace rendering should not emit PHP warnings, regardless of circular references in the trace argument objects.

## Root Cause Analysis

The error rendering pipeline:
1. An exception is thrown (e.g., `ExecutorTimeout` caught and re-thrown as `AppwriteException::FUNCTION_SYNCHRONOUS_TIMEOUT`)
2. The `Http::error()` handler in the router catches it
3. `$error->getTrace()` captures the full stack frames, including complete argument values (all injected dependencies)
4. In development mode, the trace is passed to `error.phtml`
5. The template iterates trace frames and calls `\var_export($traceItem['args'], true)` to render each frame's arguments
6. `var_export()` cannot handle circular object references — it emits warnings and produces garbled output

An existing guard at the error handler level (`json_encode($trace, JSON_UNESCAPED_UNICODE) === false ? [] : $trace`) was intended to filter out traces that cannot be JSON-encoded (including those with circular references). However, because trace arguments include PHP objects (Closures, Swoole internals, database connections) whose serialization behavior differs between `json_encode` and `var_export`, this guard does not reliably prevent the warning. The trace reaches the template, and `var_export` still encounters circular references.

**Risk level**: Low — the bug only manifests in development mode and produces warnings without breaking the error page. The primary impact is log noise and degraded debugging experience.

**Novel bug**: No prior bugs match this scope or symptoms.
